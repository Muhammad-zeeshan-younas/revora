# Recommended integrations for Revora collections

Checked 4 October 2026. Revora helps a distributor track customer debt, incoming payments, and collection follow-ups. The choices below support that workflow. They are recommendations unless marked as implemented. Keep production credentials in a secret manager.

| Need                              | Starting choice                                                         | Current status and purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| --------------------------------- | ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Customer reminders                | Meta WhatsApp Business Platform Cloud API                               | Integration code is implemented for one pilot company: approved-template sending, recorded consent, signed webhooks, delivery status, inbound replies, and controlled retry. A Meta account, approved three-variable template, credentials, and live verification remain. [Meta Messages API](https://www.postman.com/meta/whatsapp-business-platform/folder/13382743-ba8d099d-007e-4b52-b9f2-3cf3c60e4fbc), [Meta webhook examples](https://github.com/fbsamples/whatsapp-api-examples). |
| Bank receipts and Raast           | CSV import first; then the pilot distributor's bank or payment provider | CSV import works today. A provider connection would bring in payment references and settlement reports for matching against invoices. The provider and its API depend on the business's bank. [SBP Raast onboarding](https://www.sbp.org.pk/our-subsidiaries/raast/join-raast).                                                                                                                                                                                                           |
| Existing accounting or ERP system | Customer, invoice, and receipt CSV exchange first                       | CSV exchange works today. A direct connector should be chosen only after a pilot business names its actual accounting system and provides sample exports.                                                                                                                                                                                                                                                                                                                                 |
| Account email                     | Resend with a verified sending domain                                   | Password reset and invitation email code is implemented. Delivery requires `APP_ORIGIN`, `RESEND_API_KEY`, and `EMAIL_FROM`. [Resend API](https://resend.com/features/email-api).                                                                                                                                                                                                                                                                                                         |
| Database hosting                  | Managed PostgreSQL with automated backups and a tested restore process  | PostgreSQL is supported, but production hosting, backup retention, monitoring, and recovery require deployment setup. The local SQL.js file is for development.                                                                                                                                                                                                                                                                                                                           |

The WhatsApp callback is `/api/whatsapp/webhook`. Its GET request verifies the shared token; POST requests require Meta's `X-Hub-Signature-256` over the raw body. The sender is limited to `WHATSAPP_ORGANIZATION_ID` and sends only to customers with recorded consent during Karachi business hours. The approved template body must accept customer name, invoice number, and outstanding amount in that order. The required environment variable names are in `.env.example`. A live sandbox check is still needed after account setup. [Meta webhook sample](https://github.com/fbsamples/whatsapp-api-examples/tree/main/signature-validation-with-webhooks-payloads), [Meta template message example](https://www.postman.com/meta/whatsapp-business-platform/request/o65u5m5/send-message-template-text).

## Pilot sequence

1. Choose one distributor and obtain sample customer, invoice, and bank statement exports with personal details removed.
2. Confirm customer identifiers, dates, payment references, duplicates, and allocation review rules; use the existing CSV imports.
3. Test collection reminders with a human reviewer, then evaluate WhatsApp delivery using approved templates and a connected provider account.
4. Configure the email domain and production database, then test backup recovery and monitoring before handling live financial records.
5. Consider a direct bank or ERP connector only when the pilot workflow shows that CSV exchange is the bottleneck.
