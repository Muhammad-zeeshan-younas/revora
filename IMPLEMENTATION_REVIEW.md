# Revora implementation review

Reviewed 4 October 2026 against `BUSINESS_GUIDE.md`, the application code, and the automated tests. Revora tracks existing invoices, customer debt, incoming payments, and collection follow-ups for a company. This review describes a development pilot; it does not establish production readiness or customer adoption.

The tables use **☑** for implemented work and **☐** for work still needed. A checked feature may still have a separately listed production improvement.

| ☑     | Concurrent write protection         | A revision check and financial changes commit in one transaction. Competing allocations of the same receipt produce one commit and one HTTP 409.                                                    |

| ☑     | Import path optimization            | Batch duplicate checks and CSV customer resolution use indexed lookups. Normal uploads are limited to 1.5 MB and 1,000 rows.                                                                        |
| ☑     | Reminder and promise optimization   | The worker loads candidate companies rather than every workspace; promise refresh groups payments and precomputes allocation totals.                                                                |
| ☑     | Readiness and local backup          | `/api/health/ready` checks the database. The offline SQL.js backup command copies the local file and checks integrity and foreign keys.                                                             |
| ☑     | Account recovery and optional email | One-use, 30-minute password reset links revoke existing sessions after redemption. Resend can deliver reset and invitation emails after domain and credential setup.                                |
| ☑     | Invoice corrections and approvals   | Internal invoice adjustments and credit notes preserve reasons and history; write-offs require a separate owner/admin reviewer. These records do not issue statutory tax documents.                 |
| ☑     | Bank statement reconciliation       | CSV review compares credits to recorded receipts, allocations, dates, and opening/closing arithmetic, then stores exceptions. It does not reconcile a full general ledger.                          |
| ☑     | Coordinated reminder scheduling     | A database lease coordinates scheduler instances; reminder preparation remains in the durable workspace outbox.                                                                                     |
| ☑     | Sales customer territories          | Owners/admins assign customers to Sales members. Server reads and field writes are limited to those assigned customers.                                                                             |
| ☑     | Field collection drafts             | Staff can save interactions and promises in browser storage while offline and sync them with persistent request IDs when reconnected.                                                               |
| ☑     | WhatsApp integration code           | A single-company Meta Cloud API sender, approved-template parameters, consent gate, signed webhook, delivery states, reply capture, and controlled retry are implemented. Live setup is pending.    |
| ☑     | Smaller initial web bundle          | Dialogs load when opened; the main production JavaScript chunk fell from about 516 KB to 456 KB before gzip.                                                                                        |

The supported record imports are customer, invoice, incoming bank-payment, and bank-reconciliation CSV files. Staff can also attach a supporting PDF or image, such as an invoice or bank deposit slip, to a customer, invoice, or payment.

## Pakistan pilot fit

Available tools and vendor claims do not prove that every Pakistani company uses the same workflow. A distributor may use paper, spreadsheets, phone calls, and WhatsApp. Local distribution products advertise order booking, dispatch, inventory, field collection, receivables, and bank reconciliation together. Revora now has internal orders and stock reservations alongside receivables and collections, but CSV exchange with an existing billing or accounting system remains the practical pilot fit. [SAMS Online product description](https://www.sams.solutions/), [SAMS DMS features](https://www.sams.solutions/distribution-management-system-software).

SBP's FY2024–25 review reports that digital channels accounted for over 88% of retail payment transactions, and Raast P2M supports QR, IBAN, merchant aliases, and request-to-pay. This is broad payment-system data, not a measure of B2B distributor adoption. Revora can label a receipt as Raast but has no live Raast connection. [SBP payment systems review](https://www.sbp.org.pk/PS/PDF/Annual-Payment-Systems-Review-FY25.pdf), [SBP Raast P2M](https://www.sbp.org.pk/our-subsidiaries/raast/raast-person-to-merchant).

The concurrency test used a SQL.js test database and real HTTP requests. Its result does not establish PostgreSQL multi-process behavior.

The current 5,000-customer/25,000-invoice SQL.js benchmark measured 25-record invoice pages at 1 ms p50 and 2 ms p95; the full workspace read took 312 ms and serialized to 5.58 MB. These figures describe the local in-memory fixture, not PostgreSQL or a production network.
